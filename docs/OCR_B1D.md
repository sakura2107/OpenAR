## 三项处理结果

**1. 星级徽章：用户脚本使用模板匹配。**

按用户后续指示，曾加入的星级 C++ 类、导出接口及绑定已经删除；CPU/GPU 插件也已重建，二进制中没有星级专用导出符号。通用 benchmark 没有按游戏 id/星级自动路由的逻辑。

工作区临时原型使用五类模板（1～5），灰度 NCC、多尺度搜索，阈值0.85、第一/第二名差值≥0.05，否则返回不知道。三条徽章均正确，空白和随机噪声对照均拒识；中位耗时约 1.280 ms，最慢裁块5次中位数 1.649 ms。

局限必须保留：2、4 的模板取自本批已见回归徽章；1、3 取自同帧其他未评分徽章，5 取自已有繁中截图。三条成功不能证明两服、全部1～5、多种徽章样式都已覆盖。用户脚本接入及更广泛样式回放属于业务侧工作，未伪装成通用框架已实现。模板来源与截图 SHA、坐标见[测试证据](../out/ocr-audit/b1d-deliverable/模板测试证据/manifest.json)，预测/原始时长见[原型记录](../out/ocr-audit/b1d-deliverable/evidence/b1d-user-star-prototype.json)。测试结束后临时实现删除，保留证据。

**2. 日服数字：保留日文 v3，在其后增加英文 v4 第二备用。**

直接用英文 v4 替换日文 v3，会让旧 tune 中的 `789,333,348` 变为 `789.333.348`，数字从29/29降为28/29，所以未采用。最终路径为 v5主模型 → 原日文v3备用 → 英文v4第二备用。第二备用只在前级拒识或语法无效时调用；不覆盖前级已经有效的数字，不补造斜杠、倍率或百分号。

最终旧 tune 数字29/29、旧回归127/127，保持全对；新批普通数字/倍率37/37。两条原先拒识的 `×10`、`×1` 分别读为 `x10`、`X1`，按原 `b1b-v2` 规则语义正确。本轮所有倍率裁块逐条检查，见[倍率 xN 对比](../out/ocr-audit/b1d-deliverable/倍率xN逐条对比.csv)。

**3. 繁中：在 CTC argmax 前屏蔽简体类别，保留合法台湾字形。**

固定 OpenCC revision `fae2a0a911c30764e669a7d8b0591cd8e852934a`，以 [STCharacters](https://github.com/BYVoid/OpenCC/blob/fae2a0a911c30764e669a7d8b0591cd8e852934a/data/dictionary/STCharacters.txt) 生成非同形来源字集合，并保留同形/歧义项；再用同版本 [TWVariants](https://github.com/BYVoid/OpenCC/blob/fae2a0a911c30764e669a7d8b0591cd8e852934a/data/dictionary/TWVariants.txt) 的合法目标字形作为保留集合。最终屏蔽 **3802** 个 Unicode 字符，版本 `opencc-stcharacters-tw-b1d-v2`，集合写入 profile 并带来源 SHA256。原表、许可证和 provenance 均保存。

STCharacters 单表还会规范化繁体异体字，例如「群→羣」「床→牀」。初版因此误伤旧回归，未采用；v2 从固定台湾字形表恢复合法类别，不按个别错例手写替换清单。原始失败候选及日志保留作诊断。

掩码只作用于文字模型的 CTC 类别选择，blank 不屏蔽；数值主模型及两级备用不继承文字掩码。置信度仍按原模型概率和原阈值判断，没有概率重标定或识别后转换。`掃蕩`、`星野(泳裝)`、`花子(泳裝)` 均直接读对。

繁中旧 tune 规范化文字120/124→121/124；旧 CPU 回归356/362→357/362，GPU357/362→358/362，封闭集保持362/362；新批56/60→59/60、封闭集60/60。剩余的 `神名文字碎片I` 尾部漏读仍保留，按要求不处理，靠封闭集正确命中。
